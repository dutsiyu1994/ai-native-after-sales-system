**术语（首次）**：  
- **SQL**：Structured Query Language，结构化查询语言，用来向数据库「提问要数据」。  
- **SELECT**：SQL里「请取出这些列」的关键字。  
- **FROM**：指明数据来自哪张表。  
- **\***：通配符，表示「所有列」（预览方便，正式取数少用）。

## 知识点卡片 KP-M02-01

- **知识点ID**：`KP-M02-01`
- **知识点名称**：SELECT与FROM：从桌子上把列「端」过来
- **所属模块**：`M02`
- **前置知识**：`KP-M01-04`
- **学习目标（1—2条，可验证）**：
  1. 能写出从 `tickets` 取 `ticket_id, subject` 的SQL。
  2. 能解释 SELECT 与 FROM 各自负责什么。
- **零基础解释（不超过200字）**：  
  SQL最基本句式是：`SELECT 列名 FROM 表名;`。SELECT后面写你要看的字段，FROM后面写从哪张表拿。句末常用分号表示结束。这是闭环里「取数」的第一刀：先能把需要的列拿出来。
- **生活类比**：  
  食堂打菜：FROM=去哪个窗口；SELECT=只要土豆丝和汤，不要别的。
- **具体示例**：只要工单号和标题，不要正文（正文太长，晨会屏幕放不下）。
- **操作步骤/代码/命令（逐行注释）**：

```sql
SELECT          -- 关键字：我要取以下列
  ticket_id,    -- 业务含义：工单编号，方便回头定位
  subject       -- 业务含义：标题，方便人快速扫读
FROM tickets;   -- 数据来源：工单表；分号表示语句结束
```

- **业务场景对应（客服/售后/工单等）**：  
  班组长要「今日工单标题清单」投屏：只需编号+标题，不必投全部字段。
- **练习任务（可在20分钟内完成）**：  
  写出取 `ticket_id, priority, status` 的SQL并运行，把前5行结果粘贴到学习日志。
- **自测题（2—3题，附答案）**：
  1. `FROM` 能否省略？ → **不能**（必须知道数据来自哪）。
  2. 列顺序是否必须与表定义一致？ → **不必**，SELECT里写的顺序就是结果顺序。
  3. 写错列名会怎样？ → **报错**（如 no such column）。
- **常见错误与排查**：
  - 错误：写成 `SELECT tickets`。排查：SELECT后是列，表名在FROM后。
  - 错误：中文逗号。排查：SQL必须用英文逗号 `,`。
- **复用标签**：`#SQL` `#SELECT` `#零基础` `#可复用`
- **建议时长**：30 分钟
- **掌握标准**：独立写出并成功运行至少2条不同列组合的SELECT。

## 知识点卡片 KP-M02-02

- **知识点ID**：`KP-M02-02`
- **知识点名称**：SELECT * 预览与「不要滥用星号」
- **所属模块**：`M02`
- **前置知识**：`KP-M02-01`
- **学习目标（1—2条，可验证）**：
  1. 能用 `SELECT *` 预览表内容。
  2. 能说出至少2个正式取数时应写清列名的理由。
- **零基础解释（不超过200字）**：  
  `*` 表示所有列，适合你还不熟悉表结构时「先看一眼」。但正式流程（给同事报表、给程序下游）应写清列名：更安全、更省流量、字段变更时更早发现错误。
- **生活类比**：  
  搬家时「先打开衣柜看看有什么」可以用「全倒出来」；真正装箱要按清单，不能永远全倒。
- **具体示例**：预览工单全貌 vs 导出给AI分类只要 `ticket_id, content`。
- **操作步骤/代码/命令（逐行注释）**：

```sql
SELECT *        -- 预览：取出所有列（学习阶段可用）
FROM tickets;   -- 来源工单表

-- 正式取数示例：只取给模型分类用的最小字段
SELECT
  ticket_id,    -- 用于回写结果时对齐
  content       -- 模型主要阅读的文本
FROM tickets;
```

- **业务场景对应（客服/售后/工单等）**：  
  给大模型批量分类时，若 `SELECT *`，可能把手机号等敏感列也送出去——不合规。
- **练习任务（可在20分钟内完成）**：  
  写两条SQL：①`SELECT *` 预览；②只取「给AI分类」所需最小列集，并写一句为什么这样选。
- **自测题（2—3题，附答案）**：
  1. 学习阶段用 `*` 可以吗？ → **可以，用于熟悉结构**。
  2. 生产取数推荐 `*` 吗？ → **不推荐**。
  3. 字段被删时，写清列名有何好处？ → **查询立刻报错，避免静默缺字段**。
- **常见错误与排查**：
  - 错误：把 `*` 当成「所有行」。排查：`*`管列；行数要用WHERE/LIMIT控制。
- **复用标签**：`#SQL` `#SELECT` `#数据安全` `#可复用`
- **建议时长**：20 分钟
- **掌握标准**：能演示预览查询，并能写出最小字段清单的SELECT。

## 知识点卡片 KP-M02-03

- **知识点ID**：`KP-M02-03`
- **知识点名称**：列别名AS：让结果对业务可读
- **所属模块**：`M02`
- **前置知识**：`KP-M02-01`
- **学习目标（1—2条，可验证）**：
  1. 能用 AS 把英文字段显示成中文别名。
  2. 能解释别名不改变数据库里真实列名。
- **零基础解释（不超过200字）**：  
  别名是「结果表头的化妆名」。数据库列仍叫 `priority`，但你可以让结果头显示为「优先级」，方便业务阅读。AS 关键字用于指定别名（有的引擎可省略AS，建议初学写上）。
- **生活类比**：  
  护照名是英文，会议胸牌可写中文名——人还是同一个人。
- **具体示例**：晨会投屏用中文表头，减少「priority是啥」的打断。
- **操作步骤/代码/命令（逐行注释）**：

```sql
SELECT
  ticket_id AS 工单号,     -- 结果表头显示「工单号」
  priority AS 优先级,      -- 方便非技术同事阅读
  status AS 状态,
  subject AS 标题
FROM tickets;              -- 真实列名未改，只是展示名变了
```

- **业务场景对应（客服/售后/工单等）**：  
  导出给运营的Excel：表头中文，减少二次解释成本。
- **练习任务（可在20分钟内完成）**：  
  为 `channel, category, created_at` 起中文别名并运行。
- **自测题（2—3题，附答案）**：
  1. 别名会改表结构吗？ → **不会**。
  2. WHERE里应写别名还是原列名？（预告） → **多数情况写原列名**（第M03详述）。
  3. `AS` 的作用？ → **指定结果列的显示名**。
- **常见错误与排查**：
  - 错误：别名含空格却未加引号导致报错。排查：本课用无空格中文，或使用双引号/方括号按引擎要求。
- **复用标签**：`#SQL` `#可读性` `#可复用`
- **建议时长**：25 分钟
- **掌握标准**：能交付一版「中文表头」的工单清单查询。

## 知识点卡片 KP-M02-04

- **知识点ID**：`KP-M02-04`
- **知识点名称**：去重DISTINCT与计数直觉（为GROUP BY铺路）
- **所属模块**：`M02`
- **前置知识**：`KP-M02-01`
- **学习目标（1—2条，可验证）**：
  1. 能用 DISTINCT 列出所有出现过的 `category`。
  2. 能说明 DISTINCT 与「数一共多少行」不同。
- **零基础解释（不超过200字）**：  
  DISTINCT 表示「同样的值只留一份」。想知道工单分类有哪些取值，用它比肉眼翻表快。注意：它去的是结果里的重复值，不是删除数据库数据。
- **生活类比**：  
  从全班借书名单里，只想知道「出现过哪些书名」，重复书名抄一次即可。
- **具体示例**：列出售后问题有哪些类别，便于做下拉枚举。
- **操作步骤/代码/命令（逐行注释）**：

```sql
SELECT DISTINCT category   -- 只看分类字段的不重复取值
FROM tickets;              -- 业务含义：问题类型枚举有哪些

SELECT DISTINCT priority, status  -- 也可对多列组合去重
FROM tickets;                     -- 业务含义：出现过哪些「优先级×状态」组合
```

- **业务场景对应（客服/售后/工单等）**：  
  配置「分类下拉框」前，先DISTINCT看真实数据里到底有哪些类，避免漏配。
- **练习任务（可在20分钟内完成）**：  
  分别DISTINCT出 `channel` 与 `status` 的取值列表，记到学习日志。
- **自测题（2—3题，附答案）**：
  1. DISTINCT会删库吗？ → **不会**，只影响查询结果。
  2. 想数每个分类有多少单，只用DISTINCT够吗？ → **不够**，需要GROUP BY + COUNT（第2周）。
  3. `SELECT DISTINCT *` 何时有用？ → **整行完全相同时去重**；有主键时通常每行本就唯一。
- **常见错误与排查**：
  - 错误：以为DISTINCT能「修复重复录入」。排查：去重要在写入规则/主键层解决。
- **复用标签**：`#SQL` `#DISTINCT` `#数据探查` `#可复用`
- **建议时长**：25 分钟
- **掌握标准**：能独立列出样本中全部渠道与状态枚举值。
