## 知识点卡片 KP-M00-01

- **知识点ID**：`KP-M00-01`
- **知识点名称**：什么是FDE，和「会用ChatGPT」有何不同
- **所属模块**：`M00`
- **前置知识**：无
- **学习目标（1—2条，可验证）**：
  1. 能用自己的话写出FDE的一句话定义（含「现场」与「闭环」两词或其同义）。
  2. 能列出至少3个「只用聊天机器人」做不到、但FDE要做的动作。
- **零基础解释（不超过200字）**：  
  FDE（前沿部署工程师，Forward Deployed Engineer）是把AI和数据能力真正接到业务现场的人。不是只调提示词聊天，而是要取真实数据、接真实系统、让结果可被同事使用，并记录好不好用。对你而言：你会成为「能把业务想法变成可重复跑通流程」的人。
- **生活类比**：  
  会点外卖 ≠ 会开一家能持续出餐的小店。ChatGPT像「会点菜」；FDE像「进货、做菜、上桌、收评价、改菜单」整条链路的店长助理。
- **具体示例**：  
  业务说「想自动给投诉工单分类」。只用聊天：粘贴一条让AI猜类别。FDE做法：从工单表取近7天数据 → 脚本批量调用分类接口 → 结果写回表格 → 人工抽检20条 → 记录正确率12/20 → 下周再改。
- **操作步骤/代码/命令（逐行注释）**：

```text
# 本卡片无代码，完成「对照表」即可
步骤1：在笔记本写标题「FDE vs 只用聊天」
步骤2：左列写「只用ChatGPT能做的」至少3条
步骤3：右列写「FDE还要多做的」至少3条（参考：取数、落盘、反馈、指标）
步骤4：圈出你当前工作中最缺的1条，作为8周主攻点
```

- **业务场景对应（客服/售后/工单等）**：  
  售后负责人要「质检机器人」：FDE要对接质检样本、调用模型、输出对错标记、让主管抽检，而不是只在对话框里演示一次。
- **练习任务（可在20分钟内完成）**：  
  写一段120字以内的「我的FDE学习动机」，必须包含：一个真实业务痛点 + 你希望8周后能独立完成的一个动作。
- **自测题（2—3题，附答案）**：
  1. FDE是否等于提示词工程师？ → **否**。提示词是手段之一；FDE还要取数、集成、反馈与效果记录。
  2. 「演示时AI答对了」算不算闭环完成？ → **不算**。缺少可重复流程与效果记录（有分母）。
  3. 下列哪项更像FDE工作？（A）只改文案语气（B）把分类结果写回工单表并抽检 → **B**
- **常见错误与排查**：
  - 错误：把FDE理解成「会写很多代码的后端」。排查：本课程只要最小闭环，不要求大型系统。
  - 错误：目标写成「精通AI」。排查：改成可验证动作，如「能对20条工单跑通分类并记录正确率」。
- **复用标签**：`#FDE` `#职业认知` `#零基础` `#可复用`
- **建议时长**：20 分钟
- **掌握标准（能做到什么才算过关）**：  
  能向非技术同事用1分钟讲清：FDE做什么、和「会聊天」差在哪、自己8周要交付什么。

## 知识点卡片 KP-M00-02

- **知识点ID**：`KP-M00-02`
- **知识点名称**：最小闭环六步：取数→处理→调用AI/API→呈现→反馈→记录
- **所属模块**：`M00`
- **前置知识**：`KP-M00-01`
- **学习目标（1—2条，可验证）**：
  1. 能按顺序默写最小闭环六步，不漏、不乱序。
  2. 能给任意一个售后小需求标注「卡在哪一步」。
- **零基础解释（不超过200字）**：  
  最小闭环是最短、但完整可重复的工作链：①取数（把需要的数据拿出来）；②处理（清洗、筛选、整理）；③调用AI/API（让模型或服务干活）；④结果呈现（人能看见）；⑤人工反馈（对/错/怎么改）；⑥效果记录（写下正确数/总数）。少一步，就很难持续变好。
- **生活类比**：  
  家庭体重管理：称重(取数)→记录饮食(处理)→按食谱做(调用方法)→看体重曲线(呈现)→家人提醒是否作弊(反馈)→周记腰围变化(记录)。只「看了一眼食谱」不算闭环。
- **具体示例**：  
  需求「自动识别高风险VOC」：  
  ①从CSV取近200条评论 → ②去掉空文本 → ③调用风险分类API → ④在表格标红高风险 → ⑤主管抽检20条给对错 → ⑥记录「命中高风险 8/10，误报 3/10」。
- **操作步骤/代码/命令（逐行注释）**：

```text
步骤1：画六个框，从左到右命名为：取数、处理、调用、呈现、反馈、记录
步骤2：在每个框下写「输入是什么 / 输出是什么」（各一句话）
步骤3：选你熟悉的一个业务需求，把现有做法贴到对应框；空着的框画红叉
步骤4：红叉最多的那一步，就是你第1优先补课点
```

- **业务场景对应（客服/售后/工单等）**：  
  工单智能派单：取待派工单 → 提取品类与城市 → 调用派单模型/规则服务 → 在座席台显示建议组 → 组长确认或改派 → 记录采纳率（采纳数/建议数）。
- **练习任务（可在20分钟内完成）**：  
  用六步拆解「投诉分类」：每步写1句「我具体做什么」。不允许出现「优化体验」「赋能」等空词。
- **自测题（2—3题，附答案）**：
  1. 「把AI回答复制到微信发给同事」属于哪一步？ → **呈现**（若同事回复对错并你记下来，才进入反馈/记录）。
  2. 只有调用没有取数，最大风险是什么？ → **用错样本/无法复现/无法批量**。
  3. 六步正确顺序是？ → **取数→处理→调用→呈现→反馈→记录**
- **常见错误与排查**：
  - 错误：把「反馈」和「记录」合成一步。排查：反馈是判断；记录是落盘指标与案例。
  - 错误：闭环图画成系统架构图。排查：先用人能执行的动作描述。
- **复用标签**：`#最小闭环` `#FDE` `#流程` `#可复用`
- **建议时长**：25 分钟
- **掌握标准**：能默写六步，并能指出一个真实需求卡在哪一步。

## 知识点卡片 KP-M00-03

- **知识点ID**：`KP-M00-03`
- **知识点名称**：可验证学习目标与「有分母」的效果描述
- **所属模块**：`M00`
- **前置知识**：`KP-M00-02`
- **学习目标（1—2条，可验证）**：
  1. 能把模糊目标改写成「动作 + 对象 + 数量/标准」句式。
  2. 能把「效果很好」改写成至少一种带分母的句子。
- **零基础解释（不超过200字）**：  
  可验证目标=别人能检查你是否做到。句式建议：「在【数据范围】上，完成【动作】，达到【数字标准】」。「有分母」=效果必须写成分数或比率，如 15/20、75%。没有分母的夸奖无法比较本周与上周谁更好。
- **生活类比**：  
  「孩子学习进步了」vs「数学测验从 62/100 到 78/100」。后者才能决定下步练应用题还是计算。
- **具体示例**：  
  差：提升客服AI准确率。  
  好：在20条「退款」类黄金样本上，分类正确数从 11/20 提升到 ≥16/20。
- **操作步骤/代码/命令（逐行注释）**：

```text
步骤1：写出原目标（可很模糊）
步骤2：补三要素：数据范围（多少条/哪段时间）、动作（取数/分类/检索…）、标准（x/y 或 %）
步骤3：检查：如果不能打勾「做到/没做到」，继续改
步骤4：再写一句「失败时我如何知道」（例如正确数 < 16/20）
```

- **业务场景对应（客服/售后/工单等）**：  
  质检：对「服务态度」维度，人工与AI一致的条数 / 抽检总条数；而不是「质检更智能了」。
- **练习任务（可在20分钟内完成）**：  
  改写以下3句为有分母目标：①RAG更准；②Agent更好用；③SQL更熟练。
- **自测题（2—3题，附答案）**：
  1. 「正确率很高」缺什么？ → **分母（总数）与分子（正确数）及样本定义**。
  2. 16/20 与 80/100 能否直接说谁更好？ → **不一定**，样本难度与定义可能不同，需先对齐口径。
  3. 下列哪句可验证？（A）深入理解Docker（B）能用docker ps列出正在运行的容器名称 → **B**
- **常见错误与排查**：
  - 错误：分母偷偷变大却宣称进步。排查：固定Golden Dataset（黄金样本集）再比。
  - 错误：目标只有工具名「学会pandas」。排查：改成「能筛选priority=高的工单并导出CSV」。
- **复用标签**：`#Eval` `#有分母` `#学习目标` `#可复用`
- **建议时长**：25 分钟
- **掌握标准**：能独立改写2个业务口号为可验证、有分母的目标句。

## 知识点卡片 KP-M00-04

- **知识点ID**：`KP-M00-04`

  游戏任务牌：未完成前置关卡则Boss锁住；每张牌有奖励条件（掌握标准）。
- **具体示例**：  
  想学JOIN（多表关联）但WHERE（筛选）未过关 → 系统/自学计划应退回 `KP-M03-xx`，而不是硬读JOIN。
- **操作步骤/代码/命令（逐行注释）**：
