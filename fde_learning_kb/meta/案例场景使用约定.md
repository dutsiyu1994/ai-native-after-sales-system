# 学习案例场景使用约定

> 本课程的能力目标是 **FDE 最小闭环技能本身**，不绑定某一行业或岗位。  
> 「客服 / 售后 / 工单」只是默认 **学习案例（Case）**，用来承载表结构、SQL、脚本与评测练习；可整体替换。

---

## 1. 什么是「学习案例」，什么不是「业务锚点」

| 概念 | 含义 | 本课程怎么用 |
| --- | --- | --- |
| 能力目标 | 取数→处理→调用→呈现→反馈→记录 | **固定**，不随行业改变 |
| 学习案例 | 用来练习的一套虚构业务数据与故事 | **默认可替换**；当前默认用客服工单 |
| 业务锚点 | 把课程绑定成「售后培训课」 | **不采用** |

因此：学完后你应能把同一套方法迁到电商订单、销售线索、内容审核、内部审批等，而不是只会做售后。

---

## 2. 默认案例（可随时替换）

| 案例对象 | 样本文件 | 抽象含义 |
| --- | --- | --- |
| 工单 `tickets` | `assets/samples/tickets_sample.*` | 「一件待处理业务事项」 |
| 客户 `customers` | `assets/samples/customers_sample.csv` | 「事项归属的主体」 |

---

## 3. 替换映射（把案例换成你的业务）

| 默认案例字段/表 | 可替换为（示例） |
| --- | --- |
| `tickets` 工单表 | `orders` 订单 / `leads` 线索 / `claims` 理赔 / `tasks` 审批任务 |
| `ticket_id` | `order_id` / `lead_id` / `task_id` |
| `customer_id` | `user_id` / `merchant_id` / `applicant_id` |
| `priority` 优先级 | 风险等级 / 金额档 / SLA等级 |
| `status` 状态 | 订单状态 / 线索阶段 / 审批节点 |
| `category` 分类 | 品类 / 线索来源类型 / 违规类型 |
| `subject`/`content` | 备注、评论、工单正文、审核材料摘要 |
| 「售后主管」角色 | 运营负责人 / 销售经理 / 风控同学 / 业务方 sponsor |

替换时：**能力卡片 ID、学习目标、掌握标准尽量不动**；只改样本与案例叙述。

---

## 4. 标签约定

- 能力标签（课程主标签）：`#SQL` `#Python` `#RAG` `#Agent` `#Eval` …  
- 案例标签（仅标记练习故事，不表示课程定位）：`#案例-工单` `#案例-客服`  
- 废弃用法：不要用「业务锚点=售后」描述本知识库；文档中若出现 `#售后`，视为案例标签别名，等同 `#案例-工单` 语境。

---

## 5. 卡片字段写法

知识点卡使用字段名：

**学习案例对应（本课默认：客服工单；可替换为订单/线索/审批等）**

写法要求：先写默认案例中的具体动作，再用一句话提示「换到××业务时，对应的是……」。
