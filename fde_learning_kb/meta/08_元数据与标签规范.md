# 8. 元数据与标签规范

## 8.1 ID规则

| 对象 | 格式 | 示例 | 规则 |
| --- | --- | --- | --- |
| 文档 | `DOC-<域>-<序号>` | `DOC-FDE-LOOP-001` | 域大写短码 |
| 周次 | `W<两位周号>` | `W01` | 01—08 |
| 模块 | `M<两位序号>` | `M03` | 00起，与清单一致 |
| 知识点 | `KP-<模块ID>-<两位序号>` | `KP-M03-05` | 模块内递增，不复用已删号 |
| 练习 | `EX-<周次>-<MIN\|INT\|EXT>` | `EX-W01-MIN` | EXT=延伸 |
| 项目 | `PRJ-<周次>-<两位序号>` | `PRJ-W01-01` | |
| 评估 | `ASM-<周次>-<类型>` | `ASM-W01-SUM` | SUM/FORM等 |
| Rubric | `RB-<范围>` | `RB-W01-PRJ` | |
| 术语 | `TRM-<短码>` | `TRM-RAG` | 短码稳定，不随中文改名而变 |

**禁止**：用中文做ID；用空格；同一ID指代两张卡。

## 8.2 标签体系

### 必选层（每张知识点卡至少1个能力域标签）

`#SQL` `#Python` `#RAG` `#Agent` `#Eval` `#Linux` `#Docker` `#API` `#FDE` `#方法`

### 场景层

`#客服` `#售后` `#工单` `#VOC` `#质检` `#派单`

### 教学层

`#零基础` `#可复用` `#项目` `#术语` `#安全`

### 写法

- Markdown正文用反引号包裹：`` `#SQL` ``  
- 知识库若支持原生标签，导入时去掉`#`或保留，按平台配置；**本库源文件统一保留`#`前缀**便于检索。  
- 一卡建议 3—6 个标签，避免堆砌。

## 8.3 前置依赖字段

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `前置知识` | ID列表 | 卡片级，强依赖 |
| `前置模块` | 模块ID | 模块头信息 |
| `弱依赖` | 可选 | 「建议先学但不阻塞」 |

表达法：多个ID用顿号或逗号分隔：`KP-M02-01`、`KP-M02-02`。

---

## 8.4 版本字段

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| `version` | `v0.1.0` | 语义化：重大结构/兼容/补丁 |
| `doc_version` | `v0.1.0-week1` | 文档包版本，可带里程碑后缀 |
| `status` | `active` / `deprecated` / `draft` | 过期用deprecated并指向替代ID |
| `updated_at` | `2026-11-02` | 以 Asia/Shanghai 日历日为准写入 |

---

## 8.5 维护人字段

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| `owner` | `owner:curriculum` | 内容负责人 |
| `reviewer` | `reviewer:fde-mentor` | 业务准确性审核 |
| `last_editor` | Git作者 | 以版本库提交为准 |

模块文件头建议用表格写明 `维护人`；单卡可继承模块维护人，除非单卡另注。
