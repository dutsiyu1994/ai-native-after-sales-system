# 9. 更新维护规范

## 9.1 内容如何迭代

1. **只改一处真相源**：卡片以 `modules/*.md` 为准；周报文件只引用ID，不复制大段正文。  
2. **小改走补丁版**：错别字、注释澄清 → `v0.1.0` → `v0.1.1`。  
3. **结构改走次版本**：增删卡片字段、调整周顺序 → `v0.2.0`。  
4. **目标改走主版本**：闭环定义变化、能力地图重构 → `v1.0.0`。  
5. **样本与卡片同步**：改CSV/SQL样本必须同步练习「通过标准」中的期望行数。  
6. **续写周次**：新周内容合并后更新 `README.md` 导航与 `03_模块清单总表.md` 展开状态。

## 9.2 如何标记过期

在卡片顶部或模块头增加：

```markdown
> status: deprecated  
> replaced_by: KP-M03-06  
> deprecated_at: 2026-12-01  
> reason: LIMIT语法示例迁移到窗口函数对照卡
```

规则：

- 过期卡保留90天可检索，避免外链尽断。  
- 禁止直接删除已被其他课程引用的ID；先deprecated再在大版本清理。  
- 标签可加 `#过期` 仅用于检索，正文status仍以字段为准。

## 9.3 如何做版本对比

| 方法 | 做法 |
| --- | --- |
| Git diff | `git log -- fde_learning_kb/` 与 `git diff v0.1.0-week1..HEAD -- path` |
| 卡片级对比 | 以知识点ID为锚点，比对学习目标/示例/掌握标准三节 |
| 发布说明 | 每次文档包发版写 `CHANGELOG`：新增ID、变更ID、废弃ID |
| 教学影响评估 | 标注「是否要求已学习者补修」 |

### CHANGELOG 条目模板

```markdown
## v0.2.0-week2 — 2026-xx-xx
### Added
- M04 全量卡片 KP-M04-01… 
### Changed
- KP-M03-05 补充分页直觉说明
### Deprecated
- （无）
```

## 9.4 质量门禁（合并前）

- [ ] 新卡通过模板字段校验清单  
- [ ] 术语首次出现有一句话解释  
- [ ] 代码有逐行中文注释（含业务含义）  
- [ ] 练习可在宣称时限内完成（维护人自测一遍）  
- [ ] 更新模块清单展开状态与周文件链接
